ZeniTest provides native **Mobile E2E Testing** for iOS (`.ipa`) and Android (`.apk`) applications. Powered by AI vision, ZeniTest understands your app's screens directly and executes natural language steps on real devices without requiring complex code or fragile element locators.

---

## Overview & Features

- **Cross-Platform Support**: Test native iOS (`.ipa`) and Android (`.apk`) mobile applications.
- **Flexible Test Execution**:
  - **Cloud Device Cloud**: Run test suites on physical mobile devices in the cloud.
  - **Local Simulators & Emulators**: Run tests locally on iOS Simulators and Android Emulators.
- **Fast Build Caching**: Automatic build caching optimizes launch times by skipping unnecessary binary re-uploads.
- **Real-Time Visual Feedback**: View step-by-step screenshots, action breakdowns, and test execution results live in your terminal or dashboard.

## Organizing Mobile Test Cases

Organize your test cases into platform subfolders inside your main test directory (`zenitests`):

```text
zenitests/
├── web/
│   └── tc_web_login.yaml
├── ios/
│   └── tc_mobile_ios_checkout.yaml
└── android/
    └── tc_mobile_android_checkout.yaml
```

## Writing Mobile Test Cases

Mobile test scenarios use simple, human-readable YAML. For mobile tests, the application launches automatically at test start, so you don't need to specify a starting webpage URL or navigation step.

### Key Fields

| Key | Description | Required |
| --- | --- | --- |
| `id` | Unique identifier (e.g., `tc_mobile_ios_checkout`) | Yes |
| `title` | Brief summary of the scenario | Yes |
| `priority` | Priority rating (`P0`, `P1`, `P2`) | Optional |
| `expectedResult` | Expected final outcome | Yes |
| `steps` | Sequence of test actions (`act`) and visual checks (`validate`) | Yes |

### Supported Actions (`act`)

- **Tapping & Clicking**: `Tap 'Add to Cart'` or `Click 'Sign In'`
- **Text Input**: `Type 'user@example.com' into 'Email'`
- **Scrolling**: `Scroll down to view product overview`
- **Button Press**: `Press 'Proceed to Checkout'`

### Visual Checks (`validate`)

- `validate: Cart badge displays 1`
- `validate: Verify 'Order Placed Successfully!' message appears`

## Example Mobile Test Case

Save as `zenitests/ios/tc_mobile_ios_ecommerce.yaml`:

```yaml
id: tc_mobile_ios_ecommerce
title: Mobile iOS Checkout Workflow
priority: P0
expectedResult: Item added to cart and checkout completed successfully on iOS device

steps:
  - act: Tap the Add button on the Wireless Headphones product card
  - validate: Cart badge displays 1

  - act: Tap the Cart icon to open cart
  - validate: Your Cart header and Checkout button are displayed

  - act: Tap Proceed to Checkout
  - validate: Verify 'Order Placed Successfully!' text is displayed
```

## Running Mobile Tests

Execute mobile tests from your terminal using the `zenitest run` command with the `--platform` and `--bundle` flags:

<Tabs>
  <TabItem label="iOS">
    ```bash
    zenitest run --platform ios --bundle ./build/Runner.ipa
    ```
  </TabItem>
  <TabItem label="Android">
    ```bash
    zenitest run --platform android --bundle ./build/app-debug.apk
    ```
  </TabItem>
  <TabItem label="All Platforms">
    ```bash
    zenitest run --dir zenitests --bundle ./build/app-debug.apk
    ```
  </TabItem>
</Tabs>

---

## CLI Options

| Flag | Short | Description | Example |
| --- | --- | --- | --- |
| `--platform <target>` | `-t` | Filter test target platform (`web`, `ios`, `android`) | `--platform ios` |
| `--bundle <path>` | `-b` | Path to mobile app binary (`.ipa` or `.apk`) | `--bundle ./build/Runner.ipa` |
| `--dir <path>` | `-d` | Path to test directory | `--dir zenitests` |

## Secure Configuration

Store sensitive credentials or environment keys safely in your local `secrets.yaml` file:

```yaml
secrets:
  MY_TEST_USER: user@example.com
  MY_TEST_PASSWORD: securePassword123
```
